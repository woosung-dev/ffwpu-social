## 자동 선택 항목

### D1. 데이터 모델 — 컬럼 추가 vs 상태 enum 전환

- 옵션: (a) `is_hidden boolean` 1컬럼 / (b) `status` enum 컬럼으로 전면 전환 / (c) `unpublished_at timestamp`
- **선택: (a)**
- 이유: `published_at` 의 3-state 시맨틱(null/미래/과거)이 이미 코드 전반에 퍼져 있다. enum 전환은 공개·어드민 쿼리 전수 재작성이라 비용 대비 이득이 없다. `unpublished_at` 은 시각 정보를 쓰지 않으면서 nullable 판정만 늘린다.
- 영향: 마이그레이션 0016 additive 1줄. 기존 15건 전부 `false` 로 공개 유지.

### D2. 공개 필터 — 3곳 개별 수정 vs 단일 헬퍼 추출

- 옵션: (a) `publicPublishedWhere()` 3개 파일 각각 수정 / (b) 공용 모듈로 추출해 import
- **선택: (a)**
- 이유: `features/*` 간 직접 import 는 모듈 경계 규칙(ADR-033) 대상이고, 3곳뿐이라 추출 이득이 작다. 대신 세 곳 주석에 "한쪽만 고치면 샌다"를 명시하고 ADR 에도 남겼다.
- 리스크: 새 공개 쿼리가 헬퍼를 안 거치면 누락 가능. ADR-053 Consequences 에 경고 기록.

### D3. 예약글의 숨김 처리

- 옵션: (a) 예약글은 `is_hidden` 무시 / (b) 예약글도 숨김 토글 허용
- **선택: (a)**
- 이유: 아직 사용자에게 보인 적 없는 글에 "비공개" 배지를 붙이면 "예약이 취소됐나?"로 읽힌다. 예약 취소는 별도 버튼으로 존재.
- 영향: `getPublishState` 가 draft/scheduled 에서 `isHidden` 을 무시. 테스트로 고정.

### D4. 기존 `해제` 버튼 처리

- 옵션: (a) 공개 글에서 제거하고 노출 토글로 대체 / (b) 노출 토글과 병존
- **선택: (a)**
- 이유: 병존하면 "해제"와 "비공개"가 나란히 놓여 어느 쪽이 파괴적인지 구분이 안 된다. 발행일을 날리는 조작을 한 클릭 거리에 둘 이유가 없다.
- 남는 경로: 임시저장 되돌리기는 에디터의 `임시 저장` 버튼. 임시저장의 `발행`, 예약의 `예약 취소` 는 유지.

### D5. 상태 라벨 — `발행` 유지 vs `공개` 로 변경

- 옵션: (a) `발행` → `공개` 로 변경 / (b) `발행` 유지하고 `비공개` 만 추가
- **선택: (a)**
- 이유: 같은 축에 `발행`/`비공개` 가 섞이면 반대말로 안 읽힌다. `공개 ↔ 비공개` 가 짝을 이룬다.
- 영향: `STATUS_LABEL` + `ADMIN_COPY.news.statusHelp` 문구 갱신.

### D6. 상태 판정 로직 위치

- 옵션: (a) `features/news/publish-state.ts` 순수 모듈로 추출 / (b) `NewsTable.tsx` 안에 유지
- **선택: (a)**
- 이유: 클라이언트 컴포넌트 안에 있으면 테스트가 불가능하다. 이 기능의 정확성이 곧 이 함수라서 테스트로 고정할 가치가 있다. `slot-rules.ts` 와 같은 패턴.
- 영향: 신규 테스트 7건 추가 (총 129 통과).

### D7. 터치타겟 — 검증 중 발견

- Playwright 실측 36×36 으로 도메인 절대제약(44px) 위반 확인.
- **조치**: `size-11 md:size-9` — 모바일 44px, 데스크탑은 테이블 행 높이 유지를 위해 36px.

### 범위 밖으로 확인된 기존 이슈 (이번 변경과 무관)

- **dev 모드에서 `notFound()` 가 200 을 반환** — 존재하지 않는 UUID 로도 재현되는 기존 동작(PPR 스트리밍이 헤더를 먼저 전송). 404 페이지 자체는 정상 렌더되고 숨긴 글 제목은 노출되지 않는다.
- **에디터 hydration 경고** — `DateTimePicker` 의 `오전 9:00` vs `AM 9:00` 로케일 불일치. 공개 글 에디터에서도 동일하게 재현되는 기존 문제.
