# `docs/source/` — 원본 아카이브

## 이 폴더의 규칙

1. **받은 원본은 그대로 보존한다.** 형식 변환·요약·정리 모두 금지.
2. **코드 결정의 근거로 쓰지 않는다.** 코드 작업의 유일한 근거는 [`../current.md`](../current.md)다. 이 폴더는 *왜 그렇게 됐는지 추적용 아카이브*다.
3. **새 회차가 오면 추가한다.** 기존 파일은 수정하지 않고, 새 파일로 추가한다.
4. **회차 사이가 *점프*되어 있다는 사실을 인정한다.** 의도서·기획안·BI PPT 사이의 회의·중간 결정 기록은 없다. 따라서 이 폴더의 문서들이 *현재 사이트 정체성을 직접 설명하지 않는다*. 정성 영역(왜·정체성·톤)에서 갭이 있을 땐 *추론*으로 채우고 *추론임을 명시*. ADR-018 참조.

## 파일 명명 규칙

| 종류 | 형식 | 예시 |
|---|---|---|
| 요청사항·기획안 | `request-YYYY-MM-DD-주제-vN.{확장자}` | `request-2026-03-18-기획안-v5.pdf` |
| 회의록·발표자료 | `meeting-YYYY-MM-DD-주제.{확장자}` | `meeting-2026-04-22-확장회의-사회공헌단BI.pdf` |
| 기타 첨부 | `attachment-YYYY-MM-DD-설명.{확장자}` | `attachment-2026-05-22-로고시안.zip` |

날짜는 문서 작성일 또는 회의일 기준. 같은 날 여러 건이면 `-1`, `-2` 접미사.

## 무엇을 어디로?

- 받은 원본 파일 → 이 폴더에 위 규칙대로 저장.
- 요약·해석·합의된 내용 → [`../current.md`](../current.md)로 가공해서 옮긴다.
- 변경의 *왜* → [`../decisions.md`](../decisions.md)와 [`../../context-notes.md`](../../context-notes.md).
